# 0.3.1 笔记正文封面验收

2026-10-13，macOS，Obsidian 1.14.4。基于 `1537e2c`（0.3.0）开发，在独立工作区保护原工作区的其它改动。

## 用户得到的变化

- 从笔记创建的设计在每次 AI 请求中携带来源正文；连续修改和重新打开设计也会重新读取来源笔记。
- 优先读取来源笔记自己的编辑器，避免误取其它当前笔记。16,000 字以内直接发送全文，不再截取前 6,000 字。
- 长文逐段摘要，所有段落及末尾进入摘要请求；摘要使用现有文本模型，缓存随设计保存，正文变化时失效。
- 创建时的选文作为固定快照保存。明确要求读取笔记全文后切换为全文并保存范围。
- 输入框上方的笔记行可展开，查看最近使用的正文、选文或摘要。来源缺失、空正文和摘要失败明确报错。
- 来源素材以 JSON 数据放入用户消息，不进入系统指令。局部改色和离线编辑不要求读取或摘要笔记。

## 本次验证

- 回归用例先在旧逻辑上失败：模型实际请求没有来源正文。新增正文传递、超过 6,000 字的末尾事实、长文全覆盖、缓存及恢复、选区、错误和素材边界验证。
- `npm run check`：140 通过、0 失败、1 跳过；ESLint、TypeScript、生产构建通过。跳过的是已有的原生 Canvas 模板布局用例，环境缺少对应二进制。
- `npm audit --omit=dev`：生产依赖漏洞 0。没有新增依赖。
- `tests/host/note-context.js` 在独立 `qiaomu-cover-note-qa` 库使用本机合成服务，捕获 15 次真实请求；验证首次/后续、重开、来源编辑器最新内容、其它笔记不泄漏、60,039 字全文分段覆盖、缓存重用、选区恢复、主动扩为全文、缺失/空正文拦截及中英文来源预览。本地改色和缺失来源时的离线编辑无需模型请求。
- `tests/host/note-context-live.js` 使用既有 Kimi K3 文本服务，对合成 Reader 更新笔记提炼出「暂停不丢进度」及暂停位置保存、重开续读的副标题，选择方案后写入可编辑画布。真实长文摘要服务、其它提供商、Windows/Linux 未逐项验收。
- `npm run package` 校验字体文件摘要与许可，生成包含字体、素材及许可的完整 ZIP。测试仅使用合成笔记，未将用户私人正文、配置或凭据提交仓库。

## 数据与发布边界

AI 请求把笔记全文、选文或摘要发给用户配置的文本模型；长文会产生多次摘要请求。选文快照和摘要保存在 `.qcover`，分享设计时按笔记内容处理。正文图片目前只是链接，未作为视觉输入。
