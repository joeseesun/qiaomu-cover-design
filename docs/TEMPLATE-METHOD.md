# 模板方法论（借鉴 ppt-master）

[hugohe3/ppt-master](https://github.com/hugohe3/ppt-master) 是一个 AI 生成可编辑 PPTX 的项目，模板体系很成熟。它面对的是 PPT，很多规则（Master/Layout、占位符、原生形状）用不上；但有四条方法论能直接搬到封面模板上，2026-10 已经落地。

## 1. 一个事实只有一个归属

ppt-master 把“模板”拆成四类：Brand（颜色、字体、Logo 等身份）、Style（方法与视觉默认值）、Layout（品牌中立的结构）、Deck（某类重复场景）。一个字段只能归一个类，多个模板叠加时按归属解析，不会互相覆盖。

在封面产品里的对应：

| ppt-master | 本产品 | 归属 |
| --- | --- | --- |
| Layout（结构） | `src/templates.ts` 的 `build()` | 位置、网格、装饰件 |
| Brand（身份） | 模板的 `Palette` + 用户的“我的系列” | 颜色、字体 |
| Style / Deck（方法与场景） | `src/contracts.ts` | 适合做什么、能装多少字、识别度在哪 |

所以合同文件里不写颜色，也不写坐标。

## 2. 每个模板都写一份合同

ppt-master 的每个 Layout 都带一份 `design_spec.md`：页面角色、槽位容量、Signature Design Elements（“这些元素就是这个模板”）。我们给每个模板写了 `CONTRACTS[id]`：

- `jobs`：沟通任务（观点、清单、数字榜单、教程、测评、问答……），是角色而不是题材；
- `title`：标题能装多少字（槽位容量，中文按字数计，英文两个字母算一个字）；
- `keep`：识别度，即局部修改时不能删掉或改色的元素；
- `tone`：深底还是浅底。

合同会写进 AI 设计师的模板列表：标题超出容量就换模板或缩短标题，换色、换字时保留 `keep`。测试会检查每个模板都有合同，新增模板时必须同时写合同。

## 3. 自动审稿：硬规则必修，软规则只提示

ppt-master 的视觉审稿把问题分成硬规则（必须修）和软规则（明显不好才动），并规定了不准动的东西。`src/audit.ts` 把这套规则改写成封面版：

| 规则 | 含义 |
| --- | --- |
| H1 出界 | 文字超出画布 |
| H2 溢出 | 文字从卡片、色条里跑出来（倾斜的卡片和单行荧光条不算容器） |
| H3 重叠 | 标题、副标题、标签互相压住 |
| H4 对比 | 低于 3:1（文字的描边、标签自带的胶囊底都算作背景） |
| H5 平台遮挡 | 文字落在头像、播放数据条、互动按钮下面 |
| S1–S7 | 贴边、主次颠倒、中文字距超过 5%、标题超过 4 行、信息流尺寸太小、小字对比低于 4.5、装饰小字的问题 |

只有标题、副标题、标签这三种文字算硬规则。模板自带的装饰小字（期号、页眉）出问题只记软规则，和 ppt-master“只守声明过的内容”一致。

`scripts/audit-templates.ts` 把每个模板放到 6 种画布（3:4、1:1、9:16、16:9、2.35:1、5:2）上，再各配 5 种文案（4 字短标题、中等、30 字长标题、带要点、英文），流程与 App 一致：模板生成 → `layoutPass` → 避让平台遮挡区，然后评分：

```bash
npm run audit -- artifacts/template-audit --sheets --failures
```

`--sheets` 输出每种画布的总览图，`--failures` 只画出有硬问题的版面，`--only=id,id` 只看指定模板。`tests/templates.test.ts` 在常用画布上要求图库模板零硬问题。

## 4. 槽位跟着安全区走

ppt-master 规定槽位边界由安全区推出，不由示例文字推出。照此做了两处修改：

- `clearCopyOfZones`（替代逐条移动文字）：先找出平台遮挡区之外最大的空白框，再把整组文案连同它的色条、胶囊、错版回声，用同一个缩放和位移放进去，构图保持原样。挪动方向会避开模板自己的插画（圆、拱门、贴纸）。
- `layoutPass` 先把文字拉回画布内，再处理重叠，避免“拉回来正好压在标题上”。

## 本次审稿结果

1230 个版面（41 个模板 × 6 种画布 × 5 种文案）：有硬问题的从 903 个降到约 50 个，剩下的大多在图库已隐藏的 compare、ticker、impact 里。

修复的真实问题：
- 标签胶囊（BadgeBox）在 `layoutPass` 里报错，导致带标签的模板跳过最后一步排版修正。
- 平台避让逐条挪动文字，副标题被挪到标题上（X 头像区、抖音字幕区）。
- 副标题被放大后交给 Fabric 按字拆行，出现以“；”开头的行。
- 胶囊副标题不会换行，长副标题冲出画布；贴纸上 4 个字溢出圆形；英文贴纸被截成 “Guid”。
- photo 无图时白字压在浅色光斑上，对比约 2.3:1；压暗层改为文字后面至少 0.6 的不透明度（ppt-master 的出血图规则）。
- bili、ticket、split 的强调色上字对比不足 3:1；新增 `toContrast`，色相不变，只加深到够用。
- riso 横版标题叠在蓝色色块上；print 的红条装不下两行副标题；quote 的标签压在长副标题上；keyword 的倾斜标签碰到上方标签。

## 新增模板的流程

1. 在 `templates.ts` 写 `build()`：只管结构，颜色全部从 palette 取。
2. 在 `contracts.ts` 写合同：jobs、title 容量、keep、tone。
3. 运行 `npm run audit -- <目录> --failures --only=<id>`，硬问题修到零，再看一遍 `--sheets` 总览图。
4. 运行 `npm test`，合同和布局测试都要通过。
